# The QDrive engine, driven by model/engine.py.
#
# Both repositories are private and this one is public, so neither is vendored
# here the way QuantumGraph was - and neither is cloned on the box, which would
# need deploy keys on repositories we do not administer. deploy.sh sends a
# checkout of each from a machine that already has them, into vendor/ beside the
# app; MW_QDRIVE_API_SRC then points at qdrive-api's src/.
#
#   pip install -r requirements.txt
#   export MW_QDRIVE_API_SRC=/path/to/qdrive-api/src
#
# qdrive-api itself is NOT pip-installed: its modules are flat in src/ (engine.py
# does `from backend import ...`), and one of them is called engine.py, same as
# this directory's. It is loaded from an explicit path instead.

qiskit>=2.5.1
qiskit-aer>=0.17.2
pydantic>=2.13.4

# engine.py's initial_circuit chaining calls qiskit.qasm3.loads(), and plain
# qiskit does not ship the QASM3 *parser*.
qiskit-qasm3-import>=0.6.0

# Moth's QDrive is deliberately NOT listed here. It is installed from a checkout,
# on the box and on a laptop alike:
#
#   pip install -e /path/to/QDrive
#
# Listing it as `qdrive @ git+ssh://...` meant every reader of this file had to
# filter that line back out, and a filter that missed one `@` line word-split it
# into a bare `@` argument and a baffling pip error. One mechanism instead.
#
# Do NOT `pip install qdrive` - that PyPI name is an unrelated QHarbor library
# which imports cleanly while being entirely the wrong thing.
