# World specifications

A world is a set of **targets** — expectation values the QDrive engine drives the
circuit toward. Every step applies all of them to the circuit the last step
produced. There is no end to it; `MW_STEPS` (default 10) says when to stop, and
one step is one readout, so `t0`–`t9`.

One JSON file per world in this directory, named `<id>.json`. The twenty here
were generated by `../genspecs.py` with random expectation values, standing in
for real ones; hand-written files sit alongside them and need nothing special.

## The file

```json
{
  "id": "spec_n3_01",
  "n": 3,
  "seed": 1109948845,
  "fraction": 0.23,
  "targets": [
    { "expvals": {"ZZ": -1.0, "ZX": -0.5}, "qubits": [0, 1], "fraction": 0.23 },
    { "expvals": {"YY": -1.0, "IZ": 0.35}, "qubits": [1, 2], "fraction": 0.23 },
    { "expvals": {"ZZ": -1.0, "XY": 0.16}, "qubits": [2, 0], "fraction": 0.23 }
  ]
}
```

| field | | |
|---|---|---|
| `id` | required | Must match the filename. Never shown to players — worlds are named from `copy.yaml`. |
| `n` | required | How many qubits the world has, 2 or more. These are the holdings; the player's own qubit is added at index `n` and is not yours to reference. |
| `targets` | required | Applied in order, every step. See below. |
| `seed` | optional | Makes the world the same world twice. Derived from `id` when absent. |
| `fraction` | optional | Cosmetic here — the prospectus reads it. The one that matters is on each target. |

## A target

```json
{ "expvals": {"ZZ": -1.0, "XI": 0.3}, "qubits": [0, 1], "fraction": 0.3 }
```

- **`qubits`** — **exactly two**, distinct, each in `0`…`n-1`. QDrive takes pairs
  and nothing else; one qubit or three fails inside the library.
- **`expvals`** — what to drive that pair toward. Each key is a two-letter word
  over `I X Y Z`, one letter per qubit in the order given (`XI` is X on the
  first, identity on the second). Values run `-1`…`+1`; `[value, certainty]`
  also works, `certainty` weighting how hard the fit is held to it.
- **`fraction`** — `0`…`1`, how far toward the target to move each step. Most of
  what separates a placid world from a violent one. Optional; omitting it lets
  QDrive decide.

A `null` in place of a target flushes the queue at that point, so the world
updates part-way through a step rather than only at the end. It draws no gate
and constrains nothing.

## Asking for one

Enough to specify a world: **how many holdings**, **which are wired to which**,
**what each pair is driven toward**, and **how hard** (`fraction`). For example —
*"four holdings in a line, not a ring, each pair driven to ZZ = -1 hard
(fraction 0.4), except the middle pair which barely moves (0.05)"* — is a
complete request.

Worth knowing when you choose:

- **Which pairs exist** becomes the gate map, and drives the "corporate
  monopolisation" figure — the share of all possible pairs that are wired.
- **How many expectation values** in total sets the complexity word (`simple` …
  `labyrinthine`).
- **Volatility** is measured, not declared: the mean over holdings of how far
  `⟨Z⟩` travels across a clean run, `0`–`2`. A world whose holdings sit still has
  nothing to bet on. The set here runs 0.45–1.09.
- **A holding that never moves** is dead weight — nobody can trade it. The
  warmer reports these as `inert`.

## After adding or editing one

```bash
MW_STEPS=10 .venv/bin/python3 warmcache.py
```

Then **commit `_stats_cache.json`**. It holds the volatility quoted in the
prospectus, which costs a couple of minutes to compute for the whole set. The
deployed code directory is read-only, so a box that meets an uncached world
recomputes it, fails to save it, and does the same on the next call — on every
boot and every player's first move after a restart.

Changing `MW_STEPS` invalidates the whole cache the same way: entries are keyed
`<id>@<steps>`.

## Checking one

```bash
echo '{"op":"scout","circuit":"spec_n3_01"}' | .venv/bin/python3 engine.py
```

`../selftest.py` checks the properties the game rests on: that a world runs the
same way twice, that nothing about a player reaches it before they invest, and
that the run they scout is the run they invest in.
